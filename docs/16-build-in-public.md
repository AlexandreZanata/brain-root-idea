# Build in Public strategy

## Narrative

Tell the product story, not the commit log: **the AI IDE where code is not the main screen**. Each public milestone should demonstrate one visible increase in user agency, safety, evidence, or efficiency.

## Content loop

For each capability publish:

1. the user problem in one sentence;
2. a short visual before/after or end-to-end demo;
3. one honest technical constraint or failed assumption;
4. measured evidence when making a performance claim;
5. the next user-visible question, not a date promise.

Never expose private repositories, prompts, credentials, provider logs, personal browser sessions, analytics identities, or contributor data. Use purpose-built demo fixtures.

## Milestone story beats

- **Foundation:** “Why code is not BrainRoot's main screen.”
- **Shell:** “It opens a real project while everything unused stays off.”
- **Agent:** “Describe a change and watch understandable progress.”
- **Tools:** “The agent can work without getting access to your whole computer.”
- **Canvas:** “The agent builds and opens its own app.”
- **Observe/fix:** “The agent can see the UI it created and check it.”
- **Undo:** “Vibe coders can recover without learning Git.”
- **Code View:** “Code is available when wanted, absent when not.”
- **Deck:** “One visual workspace, only one heavy page consuming resources.”
- **Phone:** “A phone-shaped view inside the building environment.”
- **Governor:** “Here is the measured RAM/CPU before and after hibernation.”

## Public artifacts

Maintain a public roadmap by capability, decision log through ADRs, release notes written in user outcomes, benchmark reports with raw context, screenshots/video from deterministic fixtures, and a “what changed our mind” section when research invalidates an assumption.

## Cadence without theater

Publish when there is observable evidence. Do not manufacture daily progress, fake completion percentages, or performance wins without data. A failed experiment with a clear lesson is valid content. Avoid promising dates until the platform and distribution risks are measured.

## Replay relationship

Future Replay can reduce demo-production work by recording high-level events, but it is not telemetry and not part of MVP. Recording is local, visible, consented, editable, and redacted before export.
